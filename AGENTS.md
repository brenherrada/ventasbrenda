# Standalone — fuente y alcance

Por instrucción explícita de Bren del 7/10/2026, este repo es la única fuente activa del catálogo standalone. Las instrucciones del AGENTS.md padre que describen WordPress, WooCommerce, Docker o theme.css generado no aplican a este runtime. No modificar el theme de WooCommerce para resolver tareas de este proyecto.

**Etapa solicitada el 22/10/2026:** la venta terminó. `index.html` es ahora la convocatoria de Plot Twist Collective, sin precio ni fecha de lanzamiento y con el formulario inline existente. El catálogo y su sistema visual quedan como referencia histórica local; no volver a habilitar compra, productos, countdown o promoción en la landing. No cargar su JavaScript/CSS ni Catalogo/Ventas desde esta página. Ver la decisión y el estado local/publicado en `DESIGN.md`. El header móvil tiene solo el logo centrado, sin botón. La inscripción se amplía con propuestas de productos opcionales después de confirmar el contacto: Google Sheet privada y carpeta de Drive, aún pendientes de activación real; ver integrations/waitlist/README.md. No convertir esa carga en un requisito para anotarse.

- Stack: HTML, CSS y JavaScript sin framework; Google Sheets privada con lector directo desde Netlify y puente de Apps Script conservado para recuperación y escritura de la lista de espera; selección local y consultas por WhatsApp. Netlify sirve estáticos, /api/catalog y las vistas previas sociales de filtros.
- Leer y aplicar ../../standards/UX-UI-STANDARD.md, ENGINEERING-DELIVERY-STANDARD.md, SECURITY-DATA-STANDARD.md y adapters/html-css.md.
- Fuente visual: rediseño aprobado de este chat (REDISENO.md), tokens.css, componentes reales y assets custom; el theme MTS es referencia de lectura, no runtime ni destino de cambios.
- Leer [DESIGN.md](DESIGN.md) antes de trabajar en UI: documenta el diseño standalone vigente y sus fuentes. Contrastar el historial de REDISENO.md con los componentes y Sass actuales; la propuesta calma separada no es el diseño activo del catálogo.
- Sass es la fuente editable: scss/collective.scss organiza la landing; scss/styles.scss conserva los módulos históricos del catálogo; scss/tokens.scss, promo.scss, fonts.scss, y no-script.scss mantienen sus entradas. collective.css, styles.css, tokens.css, promo.css, fonts/fonts.css, y no-script.css son generados y NO se editan directamente. Ejecutar npm run styles:build / styles:watch; npm run styles:check verifica sincronización. npm run build compila Sass antes de preparar dist. Mantener orden de cascada, selectores, tokens CSS y contratos existentes de Netlify/Sheets; no hay bundler de JavaScript.
- Trabajar desde la raíz de este repo, comprobar rama/diff antes de editar y preservar cambios ajenos. Implementar no autoriza commit, push ni despliegue.
- Para las referencias históricas del catálogo, conservar badge=recien-agregado, categoria, búsqueda, historial, selección, reservados, vendidos, galería, carga/error/reintento y meta dinámica. Meta suma todo Catalogo, incluidos vendidos; recaudado solo TOTAL VENDIDO de Ventas. No retornar detalles de ventas desde la API. La landing vigente no utiliza esos flujos.
- Reutilizar componentes y tokens. Un único clamp en la fuente para cada valor fluido, sin overrides en breakpoints. Cards y fotos no se desplazan con hover; los botones conservan feedback aprobado.
- Revisar render desktop/mobile, teclado, cierres, foco, overflow, sticky, red y movimiento reducido. Todos los cierres usan dismiss-button e icons/dismiss.svg. Panels exteriores sin overflow hidden; scroll interior cuando corresponda.
- Push y producción: aplicar la puerta obligatoria de la sección 15 de ../../standards/ENGINEERING-DELIVERY-STANDARD.md. Un push que publique incluye seguir el deploy del SHA esperado y verificar el recorrido real en la URL pública, con persistencia comprobada cuando corresponda. Para la lista de espera, ejecutar `npm run waitlist:preflight` con el proyecto explícito y completar la prueba pública y lectura de Google Sheets descritas en integrations/waitlist/README.md. El agente se hace cargo de esos pasos antes de cerrar la entrega.
- Evidencia en output/qa/; backups en output/backups/. No incluir output, .git, node_modules, secretos o archivos históricos en dist. No se entrega ZIP.
- Registrar navegador, tamaños y limitaciones concretas; no declarar conformidad global ni validación física a partir de capturas o tests.

- Higiene solicitada por Bren: no acumular capturas, propuestas ni reportes generados de QA. Usar `npm run clean:qa` al terminar su revisión y antes de un nuevo ciclo; conservar tests y backups. No dejar artefactos temporales en la raíz.
